# Подключение Supabase — этап 1

## 1. Создать проект
1. Открой https://supabase.com/dashboard и войди в аккаунт.
2. Нажми **New project**.
3. Название: `centr-prityazheniya`.
4. Выбери регион, ближайший к основной аудитории проекта.
5. Задай надёжный пароль базы данных и сохрани его в менеджере паролей.
6. Дождись создания проекта.

## 2. Применить схему базы данных
1. В панели проекта открой **SQL Editor**.
2. Нажми **New query**.
3. Открой файл `supabase/migrations/202611050001_initial_foundation.sql` из этого проекта.
4. Скопируй весь SQL в редактор Supabase и нажми **Run**.
5. Убедись, что запрос завершился без ошибок.

Схема создаёт профили, роли, автоматическое создание профиля при регистрации и базовые политики безопасности RLS. Новые пользователи получают только роль `member`. Выдача административных ролей не открыта из браузера.

## 3. Получить публичные параметры
1. Открой **Project Settings → API** (в некоторых версиях панели раздел называется **API Keys**).
2. Скопируй Project URL.
3. Скопируй публичный ключ `anon` / `publishable`.
4. Не копируй и не публикуй `service_role` / `secret` key.

## 4. Настроить локальный проект
1. В корне проекта создай файл `.env` (рядом с `package.json`).
2. Скопируй в него содержимое `.env.example` и подставь свои URL и публичный ключ:

```env
VITE_SUPABASE_URL=https://твой-проект.supabase.co
VITE_SUPABASE_ANON_KEY=твой-публичный-ключ
```

3. Установи зависимости и запусти проект:

```bash
npm install
npm run dev
```

Команды вводятся в терминале Windows (PowerShell или CMD), не в консоли браузера.

## Важно
- Файл `.env` нельзя публиковать в GitHub. Он должен быть добавлен в `.gitignore`.
- Публичный ключ Supabase предназначен для клиентского приложения; безопасность обеспечивается RLS и серверными правилами.
- Никогда не добавляй `service_role` / `secret` key в приложение, GitHub или Vercel client-side variables.
- До запуска реальной регистрации нужно дополнительно настроить URL сайта и redirect URLs в Authentication → URL Configuration.
